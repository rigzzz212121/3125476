== Цель отчета

Основная цель данного отчета - *раскрыть ключевые аспекты работы операционных систем реального времени (ОСРВ)*, уделяя особое внимание:
====
* Фундаментальным принципам работы ОСРВ
* Особенностям планирования задач в реальном времени
* Механизмам межзадачного взаимодействия
* Практическим аспектам работы с FreeRTOS
* Проблемам синхронизации и их решениям
====
Акцент сделан на *практическом применении* ОСРВ в микроконтроллерных системах.

== Операционные системы


*Операционная система — это основа взаимодействия пользователя и аппаратного обеспечения.*


==  Понятие операционной системы

Операционная система (ОС) — это комплекс программ, управляющих ресурсами компьютера и обеспечивающих выполнение пользовательских и системных приложений.

|===
| *Функции ОС* | *Описание*

| Процессорное управление | Распределение времени между процессами
| Управление памятью      | Выделение и освобождение ОЗУ
| Файловая система        | Создание, чтение и управление файлами
| Ввод/вывод              | Работа с устройствами (клавиатура, дисплей и др.)
| Интерфейс               | Командная строка или графическая оболочка
|===

==  Операционные системы реального времени (ОСРВ)

ОСРВ ориентированы на задачи, где критична точность времени исполнения.

====
В системах реального времени задержки могут быть фатальными. Поэтому ОСРВ разрабатываются с прицелом на *детерминированность* и *минимальные задержки*.
====

=== Классификация ОСРВ

|===
| Вид | Описание

| *Жесткого реального времени (Hard RTOS)* 
| Тайминги должны соблюдаться строго. Нарушение — критично (например, управление двигателями в самолёте).

| *Мягкого реального времени (Soft RTOS)* 
| Допускаются небольшие временные отклонения. Пример — мультимедийные проигрыватели.
|===

==  Многозадачность

Многозадачность — способность ОС выполнять несколько задач одновременно.

*Варианты реализации:*

- Кооперативная — задача передаёт управление добровольно;
- Вытесняющая — ОС сама решает, когда прервать выполнение.

==  Планировщик

====
Планировщик — "дирижёр" системы, распределяющий ресурсы между задачами.
====

.Критерии планирования:
* Приоритеты
* Время ожидания
* Политика ОС

В системах реального времени используется *вытесняющий приоритетный* планировщик.

=== Как работает планировщик?
1.Сбор информации о задачах

====
Планировщик анализирует:

Приоритет задачи (статический или динамический).

Время ожидания в очереди (чтобы избежать "голодания").

Требования к CPU (длительные или короткие задачи).

Политику ОС (интерактивные задачи vs фоновые вычисления).
====

2.Выбор следующей задачи
====
В зависимости от алгоритма планирования, планировщик выбирает задачу из очереди готовых к выполнению.

Например:

Round Robin (RR) — задачи выполняются по очереди с фиксированным квантом времени.

Приоритетное планирование — задачи с более высоким приоритетом выполняются первыми.

Shortest Job First (SJF) — сначала выполняются самые короткие задачи.
====

3.Переключение контекста (context switch)
====
Если текущая задача исчерпала свой квант времени или была вытеснена (например, из-за более приоритетной задачи), ОС сохраняет её состояние (регистры, стек) и загружает контекст новой задачи.
====

4.Обратная связь и адаптация
====
В некоторых системах планировщик динамически корректирует приоритеты (например, снижает приоритет CPU-ёмких задач или повышает приоритет интерактивных процессов).
====

==  FreeRTOS

FreeRTOS — лёгкая операционная система реального времени с открытым исходным кодом.

|===
| Характеристика | Описание

| Компактность | Ядро занимает минимум памяти
| Портируемость | Поддержка множества микроконтроллеров (ARM, AVR и др.)
| API | Удобные функции управления задачами, очередями, мьютексами и др.
|===

==  Межзадачное взаимодействие (МЗВ)

МЗВ — механизмы обмена информацией и синхронизации между задачами.

Типы взаимодействия:

- Очереди
- Семафоры
- Мьютексы
- События
- Потоки сообщений
- Уведомления задач

==  Задачи

Задача (Task) — наименьшая исполняемая единица в ОСРВ.

В FreeRTOS:

- Создаётся через xTaskCreate()
- Имеет приоритет
- Выполняется с вытесняющей многозадачностью

==  Отключение планировщика и прерываний

Такие действия допустимы:

* Во время инициализации
* В критических секциях
* При необходимости предотвратить переключение задач

====
Отключения должны быть минимальными по времени, иначе возможны нарушения таймингов.
====

==  Мьютексы

Мьютекс (mutex) — средство синхронизации, предназначенное для защиты ресурсов от одновременного доступа.

.Преимущества:
* Только одна задача может владеть мьютексом
* Поддержка *наследования приоритета*
* Возможность создания *рекурсивных* мьютексов

==  Дедлок (Deadlock)

====
Дедлок — состояние, при котором задачи навсегда ожидают друг друга, блокируя работу системы.
====

.Причины:
* Циклическое ожидание
* Неправильный порядок захвата ресурсов

.Методы предотвращения:
- Тайм-ауты при захвате ресурсов
- Единый порядок доступа к ресурсам
- Избежание вложенных блокировок

== Общие выводы

1. *ОСРВ - специализированный инструмент*:
   - Обеспечивает детерминированное выполнение критичных по времени задач
   - Требует особого подхода к проектированию и реализации
   - Существенно отличается от общецелевых ОС

2. *Ключевые особенности ОСРВ*:
   - Жесткие временные ограничения (Hard RTOS)
   - Вытесняющая многозадачность с приоритетами
   - Минимальные накладные расходы

3. *FreeRTOS как популярное решение*:
   - Оптимизирована для встраиваемых систем
   - Имеет минимальные требования к ресурсам
   - Предоставляет богатый набор механизмов синхронизации

4. *Критически важные аспекты разработки*:
   - Правильное использование мьютексов и семафоров
   - Избегание ситуаций взаимной блокировки (deadlock)
   - Минимизация времени отключения прерываний
   - Грамотное распределение приоритетов задач

5. *Типичные проблемы и решения*:
   - Использование наследования приоритетов
   - Применение тайм-аутов при работе с ресурсами
   - Строгий контроль за временем выполнения критических секций

*Полученные знания позволяют*:
====
- Создавать надежные системы реального времени
- Оптимизировать использование ресурсов МК
- Избегать типичных ошибок при разработке
- Эффективно использовать возможности FreeRTOS
====
