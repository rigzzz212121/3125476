== Цель отчета 
Основная цель данного отчета - *исследовать ключевые аспекты работы с данными в микроконтроллерах*, включая:
====
* Систему типов данных и их особенности
* Принципы преобразования между типами
* Работу с указателями и адресацией памяти
* Особенности чисел с плавающей точкой
* Битовые операции и унарные операторы
====
Особое внимание уделено *практическим проблемам*, возникающим при программировании МК, таким как:
====
- Потеря точности при операциях с float
- Опасности неявных преобразований типов
- Особенности сравнения чисел с плавающей точкой
====

== Типы данных в микроконтроллерах

=== Базовые типы данных

[cols="1,1,2", options="header"]
|===
| Тип данных       | Размер (байт) | Описание
| `char`           | 1             | Символ или малое число (-128..127 или 0..255)
| `int`            | 2 или 4       | Зависит от архитектуры (на 8-bit МК — 2 байта)
| `short`          | 2             | Короткое целое (-32 768..32 767)
| `long`           | 4             | Длинное целое (±2.14 млрд)
| `long long`      | 8             | Очень длинное целое (±9.2×10¹⁸)
| `float`          | 4             | Число с плавающей точкой (±3.4×10³⁸)
| `double`         | 4 или 8       | Зависит от МК (на ARM — 8 байт)
| `bool`           | 1             | Логический тип (`true`/`false`)
|===

=== Модификаторы типов

[cols="1,2", options="header"]
|===
| Модификатор    | Пример использования
| `signed`       | `signed char x = -10;` (знаковый тип)
| `unsigned`     | `unsigned int y = 1000;` (только ≥0)
| `short`        | `short int z;` (аналог `short`)
| `long`         | `long double w;` (редко поддерживается)
|===

=== Определение размера типа

Для проверки размера используйте оператор `sizeof()`:

[source,c]
----
#include <stdint.h>
#include <stdio.h>

int main() {
    printf("Размер char: %d байт\n", sizeof(char));
    printf("Размер int: %d байт\n", sizeof(int));
    return 0;
}
----

=== Гарантированно-размерные типы (`<stdint.h>`)

[cols="1,1,2", options="header"]
|===
| Тип          | Размер (бит) | Диапазон
| `int8_t`     | 8            | -128..127
| `uint16_t`   | 16           | 0..65 535
| `int32_t`    | 32           | ±2.14 млрд
| `uint64_t`   | 64           | 0..1.8×10¹⁹
|===

=== Примеры

[source,c]
----
#include <stdint.h>

uint8_t a = 255;          // Беззнаковый 8-битный
int16_t b = -1000;        // Знаковый 16-битный
float c = 3.14;           // 4-байтовое с плавающей точкой
----

NOTE: Размеры типов зависят от архитектуры. Для переносимости используйте `<stdint.h>`.

== Размер типа данных
Размер типа вычисляется с помощью оператора `sizeof()`, например:
[source,c]
----
uint8_t size = sizeof(int); // Вернет 2 или 4 в зависимости от МК
----

== Неявное и явное преобразование типов
* *Неявное преобразование* – автоматическое приведение типов компилятором:

```cpp
  int a = 10;
  float b = a; // Неявное преобразование int -> float
```

Когда компилятор САМ меняет один тип данных на другой без вашего указания.

Например:
```cpp
int a = 5;          // Целое число
double b = a;       // Автоматически преобразует int в double
float c = 3.14f;    // Литерал float
double d = c;       // Автоматически float → double
```

* *Явное преобразование* – принудительное приведение с помощью операторов:
  
```cpp
  float c = 10.5;
  int d = (int)c; // Явное преобразование float -> int
```
Когда вы ЯВНО указываете компилятору, как преобразовать тип.


== Операторы приведения 
* `static_cast` – безопасное приведение (проверяется на этапе компиляции):
```cpp

  double x = 5.7;
  int y = static_cast<int>(x); // OK
  
```

* `reinterpret_cast` – опасное приведение (интерпретирует память как другой тип):
```cpp

  uint32_t addr = 0x12345678;
  volatile uint8_t* ptr = reinterpret_cast<uint8_t*>(addr); // Для работы с регистрами МК

```
*Почему преобразование типов плохо?*

====
- Потеря точности (например, `float -> int`).

- Неопределенное поведение при несовместимых типах.

- Опасность при работе с регистрами МК.
====

== Указатели в микроконтроллерах 

=== Что такое указатель?
Указатель — это переменная, которая хранит *адрес* другой переменной в памяти.

[source,c]
----
int a = 10;    // обычная переменная
int *ptr = &a;  // ptr хранит адрес переменной a
----

=== Зачем нужны указатели?
====
* Работа с памятью (особенно важно в МК с ограниченными ресурсами)
* Передача больших данных в функции без копирования
* Доступ к регистрам периферии (например, `GPIOA->ODR = 0xFF;`)
====

=== Основные операции
====
• `&` — взять адрес:  
  `ptr = &a;`  
• `*` — разыменовать (доступ по адресу):  
  `*ptr = 20;` // теперь a = 20  
• Арифметика:  
  `ptr++` сдвигает адрес на размер типа (для `int*` — на 2/4 байта)
====


=== Почему нельзя вычитать указатели на разные объекты?
Результат не определен, так как они могут находиться в разных областях памяти (например, стек и регистры периферии)

== Работа с битами в микроконтроллерах 

=== Установка бита (включение)
Чтобы установить бит в `1`, используем оператор `|` (ИЛИ):

[source,c]
----
PORTB |= (1 << 3); // Установить 3-й бит в регистре PORTB
----
*Как работает:*
- `1 << 3` создаёт маску `00001000` (бит №3 включён)
- `|=` делает "ИЛИ" с текущим значением регистра

===  Сброс бита (выключение)
Чтобы сбросить бит в `0`, используем `&` (И) и `~` (НЕ):

[source,c]
----
PORTB &= ~(1 << 2); // Сбросить 2-й бит в PORTB
----
*Как работает:*
- `~(1 << 2)` даёт маску `11111011` (бит №2 выключен)
- `&=` применяет эту маску

===  Переключение бита (инверсия)
Чтобы инвертировать бит, используем `^` (исключающее ИЛИ):

[source,c]
----
PORTB ^= (1 << 5); // Переключить 5-й бит (0→1 или 1→0)
----

=== Важные нюансы для МК
====
* Все операции — атомарные (выполняются за 1 такт)
* Для работы с регистрами периферии часто используют `volatile`
* Вместо цифр лучше использовать именованные биты:
====

== Унарные + и - в микроконтроллерах 

=== Унарный плюс (+)
Этот оператор *ничего не делает* с числом, просто явно показывает его знак:

[source,c]
----
int a = 5;
int b = +a; // b будет равно 5 (без изменений)
----

*Зачем нужен?*
====
1. Подчёркивает положительное значение в коде

2. Иногда требуется для шаблонов в C++

3. Может приводить операнд к числу (в некоторых языках)
====

*Пример на МК:*
```c
ADC_Value = +sensor_read; // Чётко показываем, что значение положительное
```

=== Унарный минус (-)
Этот оператор меняет знак числа на противоположный:

[source,c]

int x = 10;
int y = -x; // y будет равно -10

*Особенности на МК:*

Работает даже с беззнаковыми типами (но результат может быть неожиданным)
```c
uint8_t a = 5;
uint8_t b = -a; // Получим 251 (переполнение)!
```
Важен для вычислений:
```c
int temperature = -sensor_read * 0.25; // Обработка отрицательных значений
```

=== Когда это полезно в микроконтроллерах?
====
* При работе с датчиками (например, термопара может давать отрицательные значения)

* В математических расчётах (PID-регуляторы и т.д.)

* Для явного указания знака в константах:

== Почему 17'000'000 + 1 = 17'000'000 в float?

=== Проблема точности float

При работе с числами с плавающей точкой (`float` в 32-битных МК):

```c
float big_num = 17'000'000.0f;
float result = big_num + 1.0f; // Результат останется 17'000'000.0!
```

=== Почему так?

float хранит числа в формате IEEE 754:

====
* 1 бит знака

* 8 бит экспоненты

* 23 бита мантиссы (точность)
====

*Для числа 17'000'000:*

====
* Мантисса содержит только 23 бита значимых цифр (~7 десятичных цифр)

* Единица (1.0) теряется при выравнивании экспонент
====

=== Аналогия со стаканом
Представим, что у насс есть мерный стакан только для литров:
====
У нас уже есть 17 литров (17'000'000)

Добавляете 1 миллилитр (+1)

*На шкале стакана изменений не будет*
====
=== Решение для МК

Использовать double (если МК поддерживает)

Для больших чисел применять целочисленные типы:

```c
uint32_t big_int = 17'000'000;
big_int += 1; // Теперь будет 17'000'001
```

=== Когда это критично?
====
* В финансовых расчётах

* При работе с точными измерениями

* В навигационных системах
====

== Почему 7!=7

=== Проблема сравнения чисел с плавающей точкой


[source,c++]
----
#include <iostream>

float GetMagicSeven(float num) {
    return 7.7f / 1.1f; // Должно бы вернуть 7.0
}

int main() {
    const float Seven = 7.0f;
    float magicSeven = GetMagicSeven(Seven);
    
    if (magicSeven == Seven) {
        std::cout << "7f == 7f" << std::endl;
    }
    else {
        std::cout << "7f != 7f" << std::endl;
        std::cout << magicSeven << std::endl; // Покажет ~7.0000001
        std::cout << Seven << std::endl;       // Покажет 7.0000000
    }
}
----

=== Почему так происходит?
====
1. *Точность float*:
   - Числа 7.7 и 1.1 не могут быть точно представлены в двоичном виде
   - При делении накапливается небольшая ошибка (~0.0000001)

2. *Как хранится в памяти*:
   - Идеальное 7.0: 0x40E00000
   - Наше "7.0":     0x40E00001 (последний бит отличается)

3. *Сравнение через ==*:
   - Оператор == проверяет точное совпадение битов
   - Даже мизерная разница дает "не равны"
====

=== Вывод 
====
* Избегать точных сравнений float через ==

* Для денег/измерений использовать fixed-point арифметику

* Помнить про ограниченную точность float (6-7 значащих цифр)
====

== Общий вывод

1. *Типы данных в МК*:
   - Имеют строго определенные размеры
   - Требуют явного указания преобразований
   - Особое внимание нужно уделять работе с float

2. *Указатели*:
   - Критически важны для работы с периферией
   - Требуют аккуратного обращения
   - Арифметика указателей имеет ограничения

3. *Битовые операции*:
   - Основной инструмент работы с регистрами
   - Должны выполняться атомарно
   - Лучше использовать именованные маски

4. *Числа с плавающей точкой*:
   - Имеют ограниченную точность (6-7 знаков)
   - Не подходят для точных сравнений через ==
   - Требуют специальных методов сравнения

*Полученные знания позволяют*:

====
- Писать более надежный код для МК

- Избегать типичных ошибок

- Оптимизировать работу с ресурсами
====
